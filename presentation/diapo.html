Comment ça marche

Le robot ouvre les cases tout seul

1

Textes chiffrés

Dans le dépôt GitHub public, mais illisibles sans la clé. La clé vit dans un secret GitHub.

2

Le robot

GitHub Actions. Il calcule l’heure de Paris et ne garde que les cases dues.

3

Le site

GitHub Pages. Le navigateur ne reçoit que les cases ouvertes.

4

Mes amis

Une nouvelle case chaque jour, à minuit, sans que je touche à rien.

Ce soir : 1 case toutes les 5 min En décembre : 1 case à 00:00 Paris = 23:00 UTC Un seul réglage : « mode »

Les cadeaux bien cachés

Personne ne lit la case 24 en avance

Chemins essayés, sans succès

  • Code source : aucune case fermée n’a de texte
  • Adresses devinées (case/24, cases.json, .cle) : page absente
  • Date changée ou ?date=… dans l’adresse : rien
  • Dépôt et historique : textes chiffrés, clé jamais sauvegardée
  • Journal du robot : des numéros, jamais un texte
  • Légendes de sauvegarde : neutres, aucun titre dévoilé

Là où j’ai coincé

Le passage planifié de GitHub ne s’est jamais lancé ce soir, alors que la tâche était active.

Parade : le bouton « Run workflow » et un lancement après chaque envoi.

Vérifié avec

La skill security-audit de Cloudflare, puis le défi du voisin.

Ce que je retiens

Trois leçons pour le même brief

Chiffrer tôt

Dès le début : rien ne fuit, même dans l’historique public.

Robot tôt

GitHub peut mettre plus d’une heure à lancer le premier passage.

Légendes neutres

Une légende de sauvegarde publique peut dévoiler une surprise.

Méthode : brief et kit donnés à Claude Code, palier par palier, une sauvegarde par étape.
